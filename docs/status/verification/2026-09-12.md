### A false green, caught

The first working version of this suite reported **93/93 passing while
checking nothing**. A `.storybook/vitest.setup.ts` calling
`setProjectAnnotations` suppresses `@storybook/addon-vitest`'s own automatic
provisioning (Storybook ≥ 10.3 prints a notice saying so), and with it
suppressed the a11y `afterEach` never ran with the right annotations. Deleting
the file turned four stories red. There is no setup file now, and the reason
is written into `vitest.storybook.config.ts` rather than left as folklore.

A second one was caught during this branch's own work, and is recorded because
it is a method failure worth not repeating: the mutation cleanup for the guard
tests used `git checkout --` on `.storybook/main.ts` and
`.storybook/preview.ts`, which reverted them to `HEAD` — i.e. discarded this
branch's real changes to both — and a `just test-storybook` run then reported
exit 0 on a tree with no `@storybook/addon-vitest` and no `test: "error"`.
Every measurement above was re-taken on the restored tree. Mutation cleanup in
this repository should restore from a copy, not from `git checkout`, whenever
the mutated file is one the branch itself has edited.

### The four violations, none of them planted

| Story                                                | Element                                                         | Measured   |
| ---------------------------------------------------- | --------------------------------------------------------------- | ---------- |
| `checkout-screens.stories.tsx > Mtn Number Rejected` | the MSISDN rejection message, `role="alert"`, `text-error` 12px | **2.92:1** |
| `field.stories.tsx > Invalid`                        | `FieldError`, `text-error` 12px                                 | **2.92:1** |
| `text.stories.tsx > Tones`                           | `Text tone="error"`, 14px                                       | **2.92:1** |
| `timeline.stories.tsx > Events`                      | the per-event timestamp, `opacity-60 text-xs`                   | **2.71:1** |

AA wants 4.5:1 for body text. The first three are one cause — bumblebee's
`--color-error` used as a **foreground** on `--color-base-100`, a pair nothing
in this repository had ever measured: `theme-contrast.test.ts` and
`outcome-contrast.test.ts` both pin `--color-error` as a _background_, beneath
`--color-error-content`, which is the pair the 2026-09-07 review corrected.

**The theme was proved applied rather than assumed.** axe reported the
foreground as `#ff6266`; the repo's own `oklchToLinearRgb(0.70, 0.191,
22.216)` — bumblebee's `--color-error` as `styles.css` declares it — returns
exactly `#ff6266`. If the decorator had not run, the browser would have
painted a different palette and the number would not match.

All four carry `a11y: { test: "todo" }`: axe still runs and still reports
them, the run does not fail, and each carries the measured ratio in a comment
beside it. `src/testing/a11y-gate.test.ts` — which runs in the jsdom suite, so
in `just test-web`, so in `just ci` — fails if that set is ever anything but
those four.
