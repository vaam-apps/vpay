# 2026-09-23 — the super-linter failure #238 merged past

`lint / Super-linter` has been red on the Tauri work since #238 and nobody
saw it. This page records what was red, why it stayed invisible for three
pull requests, and the output of the local reproduction that closed it.

## Why nobody saw it

**#238 (`999a23f`, the Tauri v2 checkout plugin) failed this same check and
was merged anyway, during a GitHub Actions outage, before checks reported.**
Super-linter lints only the files a pull request changed, so:

- **#240** (`078fa3d`) touched `Cargo.toml` and `package.json` — no markdown,
  nothing for markdownlint to find, check green.
- **#241** (`dd1a48b`) touched the example's Rust and its `Cargo.lock` —
  same, check green.
- **#242**, the documentation-corrections branch, touches the documents #238
  added. The latent failure came straight back, unchanged.

So the check was not flaky and it was not new: it had been failing about
files that master already contained, and two green runs in between proved
only that those two pull requests had not read them.

## The MD056 row, which is a rendering bug and predates the Tauri work

The tenth finding is not a nit. `docs/sdks/parity.md`'s gap ledger has four
columns — `Gap | Where | Found | Owner` — and one row supplied a single
cell, so it rendered with three columns of nothing.

Introduced by **#176 (`107eff1`, 2026-09-14)**, not by the Tauri work: that
commit struck the row through and appended its `— closed 2026-09-14 (D8)`
correction, and in doing so dropped the three trailing cells the row had
carried since `fa36449`. Checked with a pipe count over every row of every
table in the file: this was the only mismatch, and it had stood for nine
days.

Before, one cell:

```text
| ~~`VpayCheckoutMode.externalBrowser` is not implemented on any platform … compiled by nobody** |
```

After, four — the three cells restored exactly as `fa36449` wrote them, and
matching every other row in the Flutter block:

```text
| ~~… compiled by nobody** | `sdks/flutter/vpay_checkout_flutter` | 2026-09-14 | SDK maintainers |
```

`SDK maintainers` rather than `closed` is deliberate and measured: of the
ledger's struck-through rows, the four dated 2026-09-07 use `closed`, and
every struck-through Flutter and Tauri row — `2026-09-13`'s real-stack row
and three of the Tauri rows — keeps `SDK maintainers`. The row's own
original value was `SDK maintainers`. Restoring it changes one cell's
rendering and invents nothing.

## Two files that should never have been linted

Both come out of #238's log and neither is fixable by editing the file.
They are excluded through `filter-regex-exclude` in
[`.github/workflows/quality.yml`](../../../.github/workflows/quality.yml),
which the org-wide `vaam-apps/.github` lint workflow passes straight to
super-linter's `FILTER_REGEX_EXCLUDE`:

- `sdks/tauri/*/permissions/{autogenerated,schemas}/` — MD041, MD001 and
  ~30 MD033 on `autogenerated/reference.md`. `tauri_plugin::Builder` in the
  crate's `build.rs` rewrites that whole tree on **every** `cargo build`, and
  it is tracked on purpose. A hand-fix survives until the next build and
  then leaves a dirty tree. `.prettierignore` already excludes these two
  directories for exactly this reason. `permissions/default.toml` is
  hand-written and stays linted.
- `tsconfig*.json` — `jsonc/no-comments`, 7+ on
  `examples/tauri-checkout/tsconfig.json`. TypeScript's own config format
  permits comments; `sdks/stripe-js`, `sdks/nodejs` and others carry
  substantial explanatory ones and were simply never linted, because no pull
  request changed them while this check was green. `tsc`, in the `web` job,
  is what actually validates these files.

Nothing else is excluded, and no rule is turned off for the tree. An
alternative was available — a `.github/linters/.markdownlint.json`, which
the org workflow looks for and steps aside for — and was not taken: it
would reach only markdownlint, leaving the JSON finding unaddressed, and the
only way it could clear `reference.md` would be disabling MD033 for every
document in the repository.

Every arm is anchored `(^|/)` rather than `^`, which is load-bearing:
super-linter matches this regex against the absolute in-container path, as
its own log shows (`/github/workspace/docs/sdks/parity.md:621`). A `^sdks/`
arm would match nothing.

## Super-linter, reproduced locally

Run rather than argued about. Docker was available and `/` had 25 GiB free.
The image is `linux/amd64` only, so the run needed `--platform linux/amd64`
on this Apple-silicon host. A scratch tree holding this branch's changed
files plus the two excluded ones, at their real repository-relative paths,
with the same default `.github/linters/.markdown-lint.yml` the org workflow
writes when a repository supplies none:

```console
$ docker run --rm --platform linux/amd64 -e RUN_LOCAL=true \
    -e VALIDATE_ALL_CODEBASE=true -e VALIDATE_MARKDOWN=true \
    -e VALIDATE_JSON=true -e VALIDATE_YAML=true -e DEFAULT_BRANCH=master \
    -v "$PWD":/tmp/lint ghcr.io/super-linter/super-linter:slim-v8.7.0
# exit 2 — and the ONLY two files with findings are the two now excluded:
#   examples/tauri-checkout/tsconfig.json                              (jsonc/no-comments)
#   sdks/tauri/.../permissions/autogenerated/reference.md  (MD041, MD001, MD026, MD033)
# zero MD040, zero MD056 — the ten original findings are gone

$ docker run … -e FILTER_REGEX_EXCLUDE='(^|/)(AGENTS|CLAUDE)\.md$|(^|/)sdks/tauri/[^/]+/permissions/(autogenerated|schemas)/|(^|/)tsconfig[^/]*\.json$' …
Successfully linted MARKDOWN
Successfully linted YAML
All files and directories linted successfully
# exit 0
```

The edited workflow was then put through the two linters that read it:

```console
$ docker run … -e VALIDATE_GITHUB_ACTIONS=true -e VALIDATE_GITHUB_ACTIONS_ZIZMOR=true …
Successfully linted GITHUB_ACTIONS
Successfully linted GITHUB_ACTIONS_ZIZMOR
```

## What this does not do

- It does not make super-linter see `master`. The check still lints only a
  pull request's changed files, so a defect in a file nobody touches stays
  invisible exactly as this one did. The caller's `validate-all` input
  exists and is not set.
- It does not gate the Tauri crate's Rust, Kotlin or Swift. Nothing on this
  page moves the gap ledger's open Tauri rows.
- It changes no code and no behaviour. Nine fence languages, one table row,
  and one CI input.
