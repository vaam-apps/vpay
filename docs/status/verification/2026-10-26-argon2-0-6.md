# 2026-10-26 — staff password hashing moves to argon2 0.6

## What this is

`vpay-api`'s staff password hashing (`staff_auth::password`, ADR-0017
decision 1) moves from `argon2` 0.5.3 to 0.6.0. The maintainer asked for it the
same day, after the authkestra 0.13.1 upgrade
([its page](2026-10-26-authkestra-0-13.md)) left the lock carrying both: 0.6.0
for `authkestra-engine`, and 0.5.3 for vpay's staff hashing.

**Nothing about a stored hash changes.** Same algorithm (argon2id, v=19), same
OWASP parameters (m=19456, t=2, p=1), same pepper as argon2's secret input,
same 16-byte salt from the OS CSPRNG. No migration, and nothing is re-hashed.

## What moved

| Before (0.5.3)                                                                 | After (0.6.0)                                                                                                                         |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `argon2 = { version = "0.5", features = ["std"] }`                             | `argon2 = "0.6"`. Its defaults are `alloc`, `password-hash` and `getrandom`. The `std` feature no longer exists                       |
| Salt: `SaltString::generate(&mut password_hash::rand_core::OsRng)`, 16 bytes   | `PasswordHasher::hash_password(password)`, which draws 16 bytes through `getrandom` 0.4                                               |
| `password_hash::PasswordHash<'a>`, borrowed                                    | `argon2::PasswordHash`, which is `phc::PasswordHash`, owned. The old path is a deprecated alias                                       |
| `secret_box` and `tokens` took `OsRng` from `argon2::password_hash::rand_core` | They name `rand_core` 0.6 directly, the same crate and the same `OsRng`. argon2 0.6 re-exports `rand_core` 0.10, which has no `OsRng` |

`Argon2::new_with_secret`, `Params::new`, `Algorithm::Argon2id` and
`Version::V0x13` are unchanged. Verification still re-hashes with the
parameters, algorithm and version stored in the PHC string, under the
hasher's secret (password-hash 0.6's `PasswordVerifier` blanket impl over
`CustomizedPasswordHasher`, which argon2 0.6 implements by copying `self.secret`).

## Compatibility, both directions

**A hash 0.5.3 wrote verifies under 0.6.** Before changing anything, I called
`hash_password` on `master` at `0fc1183c` (argon2 0.5.3). The pepper was
`argon2-0.5-fixture-pepper` and the password `a password hashed by argon2 0.5`.
It produced:

```text
$argon2id$v=19$m=19456,t=2,p=1$2bb5jERNrTFlelqeL/pC7A$+xqlhQLyeP07ASLnIw3XEZJJ242t+YwKtpwAhUoPvBo
```

That string is now a unit test, `a_hash_written_by_argon2_0_5_still_verifies`.
Under 0.6 it verifies with the right password. It refuses a wrong password, and
it refuses the right password under another pepper. Every `password_hash` row
written before this change looks like it.

**A hash 0.6 writes verifies under 0.5.3, so a rollback locks nobody out.**
After the change, `hash_password` produced:

```text
$argon2id$v=19$m=19456,t=2,p=1$gQGuDdN7khukZop9lthF9Q$boRDHAlozf2v9vVcHIMKWEEFPqaYu/4WNBhuqPoGUqo
```

The pepper was `argon2-0.6-fixture-pepper` and the password
`a password hashed by argon2 0.6`. I then ran a throwaway test on a tree still
on argon2 0.5.3 (`e289ddd3`, which is #370's head). It verified this string with
the right password and refused a wrong password and another pepper (exit 0). The
throwaway test was not committed. Rolling back to v0.14.2 after staff
passwords were set or changed under 0.6 therefore loses no sign-in.

## Lockfile

Removed: `argon2` 0.5.3, `password-hash` 0.5.0, `blake2` 0.10.6. Added:
nothing. `rand_core` 0.6.4 was already in the graph, resolved by `rsa`,
`rand` 0.8, `elliptic-curve` and others. `vpay-api` now names it directly.
`cargo deny`'s `duplicate` warning for `argon2` is gone.

## Measured

On `claude/happy-hopper-r3h6rz-argon2`, from `master` at `0fc1183c` (v0.14.2):

- `cargo fmt --all --check`: exit 0.
- `cargo clippy --workspace --all-targets -- -D warnings`: exit 0, after
  three deprecation warnings for the old `password_hash::PasswordHash` path
  were fixed by importing `argon2::PasswordHash`.
- `cargo test -p vpay-api --lib`: **458 passed, 0 failed, 0 ignored.** That is
  one more than on v0.14.2, and the new one is the 0.5-compatibility case.
  `staff_auth` alone: 27 passed.
- `cargo test --doc -p vpay-api`: 19 passed, 0 failed, 0 ignored.
- `cargo test -p vpay-server --no-fail-fast`, with no Docker daemon: the unit
  binaries pass (9 and 8). The `cli` binary ran 26 passed and 17 failed. All 17
  failures panic at `tests/cli.rs:44`, where `start_postgres` reports
  "postgres:16-alpine container starts", connection refused. There is no other
  failure. CI runs them, including `staff_add_*`, which hash through
  `hash_password`.
- `cargo deny check`: `advisories ok, bans ok, licenses ok, sources ok`. The
  same three advisory ids are ignored as before, and nothing is added.
- `just verify`: exit 0, "the fifteen gates above passed".

**Not measured here:** every test that needs Docker, including
`backends/tests/integration/tests/staff_sign_in.rs`, which signs in through
the real hashing. CI runs them, and the pull request merges only on green.

## Not done

- **No re-hash on sign-in.** Stored hashes keep the parameters they were
  written with, which are today's parameters. Nothing here changed them.
- **The OWASP parameters are not revisited.** This change is a crate bump, not
  a cost change.
