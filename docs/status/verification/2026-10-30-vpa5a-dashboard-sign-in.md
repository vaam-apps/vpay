## Sabotage

Every test the plan lists, and each guard in the code under it, was broken and
the test run. **146 mutations: 145 caught, 1 survived, and the survivor is an
equivalent mutant** (`LOGIN-5`: `apiBaseUrl === null` to `apiBaseUrl === null &&
config === null`, and `config` is `null` whenever `apiBaseUrl` is, so the two
programs are the same program). The harness is the scratchpad script
`sab/run.py`: it applies one mutation, runs the named test files, expects a
non-zero exit, and restores the file with `git checkout -- <file>`, so **the
tests were committed before it ran**. The "Tests failing" column counts failing
vitest cases; "First failing case" is the first one reported.

### What the first run found, and what was done about it

The first full run caught 134 of 147. The other 13 were not all guards that
held:

- **Four mutations were bad**, not survivors (a string I had mis-copied after
  prettier reflowed a file): reworked and rerun.
- **Three AXE mutations were syntax errors** (an opening tag changed, the closing
  one not), so the file failed to compile and "failed". They were rewritten to
  change both tags and rerun; the count above is of the rewritten ones.
- **Nine guards survived and were real gaps, each now closed with a test:**
  the signed-out cookie deletion matched `Path=/` as a prefix, so `Path=/signed-out`
  passed; the pending-enrolment decoder accepted an empty sealed half; the
  stepper's remount per question, its `preventDefault` on submit, its refusal to
  trim a password and the sign-in autocomplete tokens had no case; the
  refresh-grant scan exempted `api.ts` whole, so a `refresh_token` field there
  passed (comments are stripped now, and only the scan's own file is exempt); the
  no-dropdowns allow-list exempted a file whole, so a `<select>` added to
  `payments-filters.tsx` passed (it allows one pattern in that file now); and the
  axe rule list lacked `aria-dialog-name`, so a key sheet with an empty title
  passed the a11y suite (the account-page test, which asserts the sheet's name,
  caught it all along).
- **The old `oauth.test.ts` case "is not attempted at all when /authorize
  refused" was vacuous**: its stub never wrote to the array it asserted on, so it
  passed on any code. It records the requests it counts now; `OAUTH-7` makes the
  exchange go on after a refused authorization and fails it.
- **The harness itself discarded work once.** `git checkout -- <file>` restores
  a mutated _test_ file too, and two mutations (`DROP-7`, `DROP-8`) mutate
  `no-dropdowns.test.ts`, which I had edited and not committed: the edit was
  gone, found because a later mutation survived. It was redone and committed
  before the second run.

  and, for the sign-in screens, in Chromium through Storybook (contrast, both
  themes); `next build` compiled the routes; nothing drove the server actions
  against a real vpay. `dashboard.cy.ts` is VPA-5c, and its cases 1, 3, 4, 18 and
  19 plus enrolment are the ones that will show whether the cookie jar, the
  redirects and the code leg work through a real Next server.
- **The code leg is proved against a stub.** `oauth.test.ts` checks the request
  this app puts on the wire (the PKCE challenge, the verifier, the redirect URI,
  `redirect: "manual"`); no run has followed a real `302` from a real
  `/oauth/authorize` to a real token.
- **No Rust ran.** `cargo`, `clippy`, the integration suites and the Helm checks
  are untouched by this ticket; `verify` builds the xtask only. `helm-check`
  (needs `helm` and `kubeconform`) and `docs-check-citations` (needs `gh`) were
  not run.
- **`verify-ui` runs on tracked files**, so the page and the new components were
  staged before it.
- **The key-sheet's Vaul drawer under a real touch** (drag to dismiss, the
  keyboard) was not exercised; the sheet opens, names itself, and closes in the
  tests.
- **Which credential wins when a browser holds both a session and a key** is not
  decided here: this app signs nothing, so it cannot send both. VP-6b decides.
